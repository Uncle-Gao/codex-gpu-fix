# 排查过程

## 时间线

### 第一阶段：GPU Flag 尝试（全部失败）

尝试通过 Electron/Chromium 命令行 flag 修复，共测试 7 个方向：

| Flag | 效果 |
|------|------|
| `--use-angle=metal` | bug 仍在，性能略有提升（保留） |
| `--enable-features=Metal` | bug 仍在 |
| `--disable-gpu-rasterization` | bug 仍在 |
| `--disable-blink-features=CSSBackdropFilter` | bug 区域变纯白（不是透明），说明方向对了但方法不对 |
| `--in-process-gpu` | **修复了 bug**，但 UI 明显卡顿（GPU 和渲染挤在同一进程） |
| `--disable-native-gpu-memory-buffers` | bug 仍在 |
| `NSSupportsAutomaticGraphicsSwitching` (plist) | bug 仍在，且触发了钥匙串密码弹窗 |

结论：纯 flag 路线走不通。`--in-process-gpu` 证明问题在 GPU 进程 IPC，但不能用——性能代价太大。

### 第二阶段：CDP 远程调试定位

开启了 `--remote-debugging-port=9222`，通过 Chrome DevTools Protocol 连接进行运行时诊断。

#### 尝试在浏览器 DevTools 中调试

访问 `https://chrome-devtools-frontend.appspot.com/...?ws=localhost:9222/...` 失败。
原因：HTTPS 页面不能连接 `ws://` WebSocket（Mixed Content 策略）。

解决：改用 Node.js 脚本直接走 CDP WebSocket，绕过浏览器限制。

#### 构建交互式 CSS 属性开关面板

编写 `cdp-toggle.mjs`，通过 CDP 注入一个可拖拽的调试面板，支持 14 个 CSS 属性实时开关：

- backdrop-filter, transform, will-change, contain, isolation
- content-visibility, border-radius, overflow, box-shadow, opacity
- mix-blend-mode, filter, clip-path, mask-image

每个属性点击即时切换，全局应用 `!important` 规则。

#### 关键发现

逐一测试后发现：**单独切换 `backdrop-filter` 即可完全消除白色透明区域**。

其余 13 个属性均无效果。`border-radius` 虽然也消除了白色区域，但会让全局圆角消失（效果太粗暴）。

### 第三阶段：尝试修改 app.asar（失败）

方向：直接修改 Codex 打包文件，在 HTML 中注入 CSS。

**被 Electron AsarIntegrity 阻止**。

`Info.plist` 中 `ElectronAsarIntegrity` 键存储了 `app.asar` 的 SHA-256 hash。修改 asar 后 hash 不匹配，启动报错：

```
FATAL:electron/shell/common/asar/asar_util.cc:143
Integrity check failed for asar archive
```

尝试用 `shasum -a 256` 重新计算并写回 plist，始终不匹配。Electron 的 hash 计算方式与标准 shasum 不同（可能涉及内部文件排序或元数据剥离），无法逆向。

结论：修改 asar 这条路永久封死。

### 第四阶段：尝试 preload 脚本（失败）

以为 Electron 有 `--preload` CLI flag，实际没有。`preload` 是 `webPreferences` 的 JS 选项，只能在主进程代码中设置，不能通过命令行传入。

### 第五阶段：CDP 自动注入（当前方案）

方式：wrapper 脚本启动 Codex 后立即运行 Node.js 注入器，通过 CDP 轮询等待页面就绪，注入 `<style>` 元素。

#### 注入时机优化

最初版本有两层轮询：
- Shell 层：curl 每 0.5s 检测 CDP 端口可用（最多 30 次 = 15s）
- Node 层：每 0.5s 重试找页面（最多 40 次 = 20s）

总延迟可能达到数秒，用户能看到 bug 闪烁。

优化后：Shell 层去掉轮询，Node 层改为 100ms 轮询，单循环最多 300 次（30s）。页面就绪后即刻注入，通常 < 500ms。

### 第六阶段：圆角渲染问题（未完美解决）

`backdrop-filter: none` 修复白色区域后，圆角渲染质量略有下降。原因：

Intel GPU 上 `border-radius` 的抗锯齿本身质量一般。原本 `backdrop-filter: blur()` 强制创建合成层，意外地改善了圆角渲染。禁用它后，圆角回到核显默认水平。

尝试用 `clip-path: inset(0 round Xpx)` 替代 `border-radius`——效果无改善。用户选择接受当前状态。

### 第七阶段： LaunchAgent 自动修复

Codex 自动更新会替换整个 `.app` bundle。创建 LaunchAgent 监控 `/Applications/Codex.app` 修改时间，检测到 wrapper 被覆盖后自动重新应用修复 + 签名。

10 秒防抖机制防止 codesign 修改 app bundle 后触发自身无限循环。
